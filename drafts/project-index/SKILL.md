# Project index

The index is `INDEX.md` beside this file. Read it fresh each session — it updates as the corpus
and this index evolve. Entries map terms and identifiers to their canonical files; the files
carry the text.

## Steps

1. Read `INDEX.md`. It is short; read it whole.
2. Resolve a term or identifier by its registry entry, then read the cited file — the index
   tells you where the definition lives, the file tells you what it says.
3. When you encounter a defined term, identifier, or corpus file the index lacks, add a
   one-line entry: scope, canonical path, status. Date it and flag it
   `[agent-added]` — the flag clears at owner review.
4. Identifiers originate in the corpus. When a new identifier family or definition seems
   warranted, propose it to the owner; registration follows adoption.

## Boundaries

- Specificity model: prompt-specified behavior, conventions, free implementation choices.
  "Requirement" appears in prose as plain description; the corpus carries one project
  requirement — conformance with the normative prompt.
- Statements follow M-Affirmative: entries say what a thing is and where it lives.
- The index cites corpus content by path and identifier; wholesale restatement lives
  in the corpus itself.
- `C:\Project` is read-only from `C:\Harness`. Index updates that touch corpus files wait
  for owner direction.
